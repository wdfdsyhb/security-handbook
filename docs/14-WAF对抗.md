# 14 WAF 对抗

> 绕 WAF = 想安全工程师之所想——人写的规则必有遗漏。基于攻击特征的 WAF 永远发现不了未知攻击，0day 检测不属于 WAF。

## 五类绕过框架（体系化记忆）

### 1. 请求真实 IP 绕过（性价比最高）

云 WAF（阿里云盾/腾讯 T-Sec/Cloudflare 类）多以 **DNS CNAME** 形式部署——先探测目标真实 IP（历史 DNS 记录、子域名直连、SSRF/邮件头泄露、C 段扫）直连源站，流量根本不过 WAF。

### 2. 检测内容范围绕过

WAF 出于性能**只检测前几 K/几十 K 内容**——用垃圾数据填充请求体，payload 放尾部。文件上传同理：超大 multipart 前Section 填充。

### 3. 协议盲区绕过

- 特殊 HTTP 请求方法（PUT/PATCH/自定义方法）
- 协议解析不一致（前后端/设备与源站对同一请求理解不同——与请求走私同根）
- 分块传输（chunked）让 WAF 拿不到完整 body
- HTTP/2 降级差异

### 4. 检测规则绕过（三板斧）

- **编码**：urlencode、unicode、多重编码、大小写、换行符
- **填充符号**：注释符、空格换 `+`、`\x00`、`%20`、内联注释
- **sqlmap tamper 脚本**批量组合

MySQL 特殊字符处理与语法特性：`id=1.0union%20select`（数字类型边界）、条件注释 `/*!12345union*/`。

### 5. 文件包含/路径变形

相对路径/绝对路径变形、`../` 编码变体（见 06 章路径穿越）。

## 绕过用例化（对抗纪律）

**把绕过手法沉淀成标准化用例集**，对新目标逐项过，而不是每次凭灵感：

```
请求方法：GET/POST/PUT/PATCH/自定义
请求大小：正常/超长填充
编码：无/单次/多重/unicode/分块
边界：参数间/头尾/字段重叠
协议：HTTP/1.1 / HTTP/2 / chunked
```

测 WAF 能力三步法（自建靶场）：①自建带漏洞站点 ②扫描器跑基本盘 ③绕过技术标准化成用例集逐项人工过。

## 部署形态识别（对绕过方式的选择）

| 形态 | 特征 | 绕过要点 |
|------|------|----------|
| 云 WAF | CNAME 解析到厂商 | 找真实 IP 直连 |
| 硬件串联 | 网关路由可见 | 协议盲区+规则绕过 |
| 旁路仅检测 | 不影响流量 | 慢速无告警风险（但可被溯源） |
| 反向代理 | 反代特征头 | 与走私/缓存投毒联动 |

**HTTP 解码失败动作若设为"放过"，畸形编码载荷可直接穿透**（部分设备默认配置）。

## 攻击语句已知特征（知己知彼）

WAF 内置检测目标：`alert('xss')`、`or '1'='1`、`union select`、`sleep()`、`eval($_POST[...])`、目录遍历 `%2f%2e%2e%2f`、SMB 爆破规则 50363、SMB 爆破统计 20384（绿盟 IPS 规则号举例）。

**IPS 归并机制**：同源目同事件默认 3600 秒只告一次——慢速低频攻击天然稀释告警（蓝队盲区）。

## 面对强 WAF 的战略选择

1. 换入口：不硬刚主站，打 APP 接口/小程序/边缘业务（WAF 覆盖差）
2. 换通道：真实 IP 直连、邮件协议（SMTP 钓鱼）、第三方跳板
3. 换姿势：逻辑漏洞（无特征可查——参数篡改/越权与正常请求无异）
4. 新手纪律：**遇 WAF 直接换目标**，不必硬绕——目标遍地都是
