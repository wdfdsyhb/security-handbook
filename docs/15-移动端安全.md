# 15 移动端安全

> 移动端 API 防护通常弱于 Web 主站；App/小程序是护网里防守资产盘点最弱的一环（测试账号免登录、内部 app 安全松散、逻辑上难发现）。

## APP 渗透流程

1. **抓包**：Burp + 模拟器/真机代理；系统证书信任（Android 7+ 需 Magisk 模块 Move Certificates 或改 network_security_config）
2. **证书锁定（SSL Pinning）绕过**：
   - Android：Frida + objection、JustTrustMe（Xposed）、DroidSSLUnpinning
   - iOS：越狱 + SSL Pining Disable
3. **静态分析**：jadx 反编译（Java 层）、apktool 拆资源、MobSF 一键静态+动态
4. **动态 hook**：Frida（runtime hook）、Xposed（持久 hook）
5. **测试重点**：全部 API → 当 Web 打（IDOR/逻辑/注入）；本地存储（SharedPreferences/sqlite 明文密码）；日志泄露（logcat）；硬编码密钥（strings.xml、const）

## APP 攻击面清单

- **API 层**：抓包后等同 Web——越权（user_id 改包）、签名校验绕过、旧版本接口
- **本地数据**：未加密存储、剪贴板敏感信息、备份泄露（adb backup）
- **组件暴露**：exported Activity/Provider/Receiver（deeplink 未校验 → 任意页面拉起/参数注入）
- **加固与脱壳**：360/腾讯乐固/梆梆加固 → Frida-Fart（脱壳 dump dex）
- **混淆对抗**：反调试检测绕过（改 Frida server 名字/端口）、root 检测绕过（hide）

## 小程序

- 反编译：解包工具（unveilr/wxappUnpacker）拿源码 → 搜 API 路径、appid/secret、加密逻辑
- **测试微信号免登录**、测试小程序测试账号——内部测试环境的鉴权常最弱
- 抓包：PC 端微信小程序配 Burp 代理即可
- 泄露源：前端源码里的接口、云函数调用、测试环境地址

## 移动端业务安全

- 手势密码：本地校验绕过（hook 或改包）、截图记录触点还原
- 设备指纹：改机工具（Xposed 模块）对抗风控
- 短信验证码：同 Web 端测（轰炸/回显/爆破）——**各电商验证码 URL 换手机号即轰炸平台原理**
- 支付：客户端验签不可信，服务端二次校验缺失即逻辑洞

## 逆向基础（滴滴笔试考点）

- JNI 命名规则：`Java_包名_类名_方法名`
- ARM32 寄存器：R0-R3 传参、SP/PC/LR
- 加壳检测：查.dex 文件头（壳特征）、运行时 dump 修复
- 宏病毒分析：office 宏（VBA）解码、WannaCry 特征（永恒之蓝+文件加密勒索）
