# 02 方法论总纲

> 这一章是全书的操作系统：不管打什么洞，流程、纪律、优先级都在这里。

## 五阶段挖掘工作流

```
Intake(接单) → Recon(被动侦察) → Enum(主动探测) → Hunt(漏洞探测) → Report(提交)
```

### Phase 1 · Intake 接单

四项 checkpoint 缺一不可，缺什么补什么，不要假设：

- **In-scope**：可测域名 / IP 段 / app / endpoint（逐条列出）
- **Out-of-scope**：禁测项（逐条列出）
- **规则**：赏金档位 / 漏洞披露窗口 / safe-harbor / 测试标识 header（如 `X-Bug-Bounty:<handle>`）
- **时间盒**：6 小时 / 单日 / HW 驻场 / 月度兼职

### Phase 2 · Recon 被动侦察

**禁止任何主动发包**（不扫端口、不爆路径、不发 payload）。产出：不接触目标得到的资产清单，来源至少 3 种：

- CT 日志（crt.sh / Censys）
- Wayback / CommonCrawl 历史快照
- GitHub dorks（`org:target password|api_key|SECRET|.env`）
- FOFA / Shodan favicon hash
- SecurityTrails / DNS 历史
- ASN / IP 段（bgp.he.net）

### Phase 3 · Enum 主动探测

产出**活资产矩阵**：`域 → 端口 → 服务 → 指纹 → JS endpoint`。

命中国产指纹（weaver/seeyon/tongda/landray/yongyou/kingdee/hikvision/dahua）→ 上国产指纹库+默认口令库；命中银行/支付 → 走金融行业垂直 playbook；命中运营商/BOSS → 走电信 playbook。

### Phase 4 · Hunt 漏洞探测

每个候选目标：按入口信号选 playbook → 按「参数频率表」挑入口 → 按「payload 库」探测 → 被 WAF 拦走绕过决策树 → 命中立即存 HTTP 包/截图。

**反幻觉纪律**（同样适用于人肉挖洞）：

1. payload 必须有出处（playbook/cheatsheet），不凭记忆生成变体
2. 引用案例前必须核实存在
3. **无证据不下结论**——没有 HTTP 包/截图/视频，只能写"待验证/假设"，不写"已确认"
4. **出 scope 立即停**

### Phase 5 · Report 提交

合规红线自检 → 用模板 → 三段式：标题（≤80 字精确到 endpoint+漏洞类型）→ 重现步骤（每步可执行带 HTTP 包）→ 影响+修复建议（CVSS vector + 业务影响）。

## 攻击优先级（性价比排序）

综合 88636 条乌云案例统计与 620 条 writeup 的结论：

1. **IDOR/越权** — 最适合手工、命中率最高、几乎每个业务系统都有
2. **认证流全家桶** — 注册→登录→找回→2FA→会话，按 checklist 逐项过
3. **业务逻辑** — 支付/优惠券/竞态，无法自动化=竞争少
4. **未授权访问** — Actuator/Swagger/Redis/MongoDB，扫描器可批量
5. **信息泄露** — .git/.env/heapdump/备份文件
6. 注入类（SQLi/命令注入）— 老但有效，非常规注入点是新增长点
7. XSS — 单独低危，升级链（ATO）才值钱
8. 高难高回报：请求走私、原型污染、GraphQL、DNS 重绑定

**时间不够时的取舍**：SQL 注入、文件上传、任意文件下载、接口非授权访问、垂直越权五项优先 + 中间件组件版本对齐。

## 测试通用方法论（黑盒三步）

1. **先对比正常/异常响应的差异，反推后台判断逻辑**——上传、验证码、签名校验都适用
2. **分段流程挑"假设外参数"打**——开发者的假设（"进到第二步说明第一步已通过"）就是漏洞
3. **组合拳放大危害**——SSRF→内网未授权→RCE；XSS→管理员 cookie；越权→他人余额。单个低危组合成链才定高危

## 信息资产视角

- **资产表即攻击路线图**：防守靠资产梳理收敛攻击面，攻击者按资产表（IP/端口/Web/归属）测绘。
- **边缘段/测试机是最佳突破口**：常不关 debug、弱口令、不入防护套餐。
- **新上线业务 = 新代码 = 未加固**：盯厂商公众号动态，第一时间测。
- **非普通用户权限是薄弱环节**：商家/合作方/签约作者入口的防护普遍弱于 C 端。
- **移动端 API 防护通常弱于 Web 主站**。
- **新功能上线期是黄金窗口**：新代码没经过加固，错误消息还是金矿（无效值返回有效值列表）。

## 证据与提交纪律

- 命中后立即保存：HTTP 原始包、截图、时间戳；报告五要素见第 19 章。
- **不可逆操作只重放"登录类"数据包**证明存在即可——服务未授权测试绝不用带 flushall 的 exp（清库=破坏=违法）。
- 403 不是终点：换方法（GET→POST）、换角色、换版本路径、加 `X-Forwarded-For: 127.0.0.1` / `X-Original-URL` 四种姿势各试一遍。
