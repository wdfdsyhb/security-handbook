# 19 SRC 实战与 CNVD 报送

## 平台选择（新手排序）

1. **漏洞盒子 / 补天**：范围广、国内站点都收、难度低——先读平台收录标准再挖（某平台不收反射 XSS 就别浪费时间）；严格读测试范围，越界=非法测试
2. **各厂 SRC**（腾讯/阿里/京东/字节等）：范围小、内卷、但流程规范
3. **EduSRC / 学校系统**：安全性低、案例多、易凑数（CNVD 案例）
4. CNVD/CNNVD：证书与编号路线

乌云/漏洞银行已死，老文章里的 17 平台清单别再当现状用。

## CNVD 证书细则（高价值干货）

- **通用型门槛**：中危及以上（CVSS2.0≥4.0）+ 厂商注册资金 **5000w 以上**
- **黑盒案例结构**：**10 个测试案例（3 个完整复现 + 7 个其他，越多越好）**
- **事件型**：需高危 + 重要机构（党政机关、央企、部委直属）
- **案例凑数流程**：一个通用型漏洞用 fofa body 特征 / 谷歌语法（标题、URL、公司名）/ 厂商官网客户列表，在多家单位复现即可凑满 10 案例
- **目标定位三路**：注册资金超 5000w 的网络科技/软件公司（产品站页脚"技术支持：xx网络科技"）；白盒审计大厂 CMS；EduSRC 学校系统
- **白盒案例纪律**：只交源码漏洞点+代码调试过程截图，**不混写黑盒案例**（混写会被审核误判，需邮件申诉）
- 定级参考：中危=任意密码重置/越权/SQL 注入/绕过登录；高危=命令执行/文件上传
- 拿到 shell 找不到足够案例时：下载管理员备份的源码，转白盒审计出证书

## 报告五要素

1. **接口地址（Target）**——精确到 endpoint
2. **来源地址（Referer）**——从哪个页面/入口发现
3. **Payload（Raw）**——完整 HTTP 原始包
4. **利用步骤**——每步可执行、可重现
5. **危害描述**——业务影响，不是技术名词堆砌

其他纪律：不同类型/业务线漏洞**分开提交**；报告内容不传第三方网盘；按审核者视角写（他 5 分钟内要能重现）。

## 定级与危害提升链

**定级公式 = 敏感数据有无 + 利用成本 + 危害面积**；严重级 = 业务影响大 × 范围广（测试库漏洞不算严重）。

提升链（单点低危 → Critical）：

| 单点 | 升级方向 |
|------|----------|
| XSS | → 窃取 cookie → ATO；+CSRF 组合 |
| SSRF | → 云元数据凭证 → 内网 RCE |
| IDOR | → 遍历 = 变相脱裤（危害面积） |
| 逻辑漏洞 | → 资金损失/他人余额支付 |
| 未授权服务 | → 写文件 → RCE |

**影响 > 检测**：证明凭证窃取/RCE/数据外泄，不是"发现 XSS"。

## 提交技巧（620 writeup + 实战归纳）

1. **链式漏洞**：开放重定向+SSRF、SQLi+文件写入=RCE——组合上报
2. **完整文档**：截图、HTTP 请求、实际提取的数据
3. **新颖技术**：解析器混淆、mXSS、WAF 绕过链
4. **盲漏洞需证明**：Interactsh/bXSS 实际回连记录
5. **A/B 账号对照**：越权测试必须有对照（防误伤+防平台质疑）
6. self-XSS 别直接交，先想升级路径
7. 403 不是终点：换方法/换角色/换版本/换路径四种姿势
8. **403/404 站点更易出洞**：先扫目录再说话
9. 只对登录框测试时，多注意子目录和接口
10. 入手点优先：意见反馈/上传等提交表单、付款金额校验、改密码 sign 值替换、数值溢出——**新手从并发逻辑漏洞开始**（每个网站多少都有）

## 目标选择经验

- 业务安全两薄弱环节：**非普通用户权限**（商家/合作方/签约作者——可社工获取测试账号）+ **新上线业务**（盯公众号动态第一时间测）
- IP 段分核心段/边缘段/云服段——边缘段测试机（不关 debug+弱口令）是最佳突破口
- whois 注册人邮箱 → 扩展域名；备案号 → 同公司资产
- 强安全策略下也有强弱口令：外部公开撞库字典匹配是现实威胁
