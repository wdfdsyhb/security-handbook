# 12 服务器与中间件

## 未授权服务清单（17 项，批量扫端口后逐个对照）

Redis(6379)、Jenkins(8080)、MongoDB(27017)、ZooKeeper(2181)、Elasticsearch(9200)、Memcached(11211)、Hadoop、CouchDB、Docker(2375)、Varnish、proxool、nfs(2049)、samba(445)、influxdb、Rsync(873)、Cassandra(9042)、Resin。

**测试纪律**：端口类只模拟未授权登录数据包（wireshark 抓包重发到测试服务器证明存在即可）；web 类凭未授权 response 证明存在。**很多 exp 不可逆——绝不用带 flushall 的 exp（清库=破坏）**。

### Redis 未授权（最高频）

- 成因：6379 绑 0.0.0.0 + 无密码 + 防火墙无防护
- 两条固定利用线：写公钥（authorized_keys 登录）或写计划任务（crontab 反弹 shell）
- 危害取决于 Redis 启动权限（root 跑=写 root 的 ssh key）
- 修复判定：加密码、绑 127.0.0.1、防火墙白名单、降权 nobody 启动

### 组合拳（高级利用=串链）

- ssrf + 内网 mysql 未授权 → RCE
- 未授权接口 + XXE
- redis 写文件提权
- Memcached 未授权做 DDoS 反射放大（伪造源 IP 的 UDP 查询）

## 中间件 RCE 面（优先打）

**Struts2**（s2-045/048/057 等）、**Weblogic**（T3 反序列化/弱口令 war 部署/SSRF）、**fastjson**、**jackson**、Shiro（rememberMe 反序列化）、ThinkPHP（5.x 远程命令执行）、Tomcat（PUT 上传/manager 弱口令）、JBoss（反序列化）、IIS（PUT/解析漏洞）、Spring Boot Actuator（`/actuator/heapdump` 拿内存凭据）。

新 CVE 处理流程：按编号搜 POC（CVE/CNVD/CNNVD/SecurityFocus 按 Bugtraq ID 找 exploit）。

## 弱口令（服务器侧产出主力）

- 数据库/FTP 批量爆弱口令：内网开发为方便常设弱口令，扫数据库成功率极大
- 高危端口清单：21/22/23/445/1433/3306/3389/7001/8080/27017
- 远程管理卡（Dell `root:calvin`、HP/IBM/HUAWEI 默认表）
- 字典构建见 18 章蓝队篇（防守字典=攻击字典）

## Java 代码审计速查（白盒时用）

- 两大来源：编码不当（输入输出未过滤、权限控制不完备、**MyBatis 未用预编译**）+ 第三方组件不当（低版本漏洞组件、调试模式未关）
- **先审 POM 文件找低版本组件**（对应 CVE 直接打）；再配置文件找错误配置
- 高危组件清单（迭代中）：Struts2、Commons Fileupload、Commons Collections、fastjson、Shiro、Log4j2、Spring Boot
- 时间有限优先级：SQL 注入、文件上传、任意文件下载、接口非授权访问、垂直越权 + 组件版本

## 白盒审计三分法

1. **代码静态审计**：找危险函数（sink）并向上回溯调用点是否可控——grep 定位再人工回溯
2. **代码动态审计**：理解功能后运行程序单步调试
3. **运行环境审计**：中间件/数据库/插件（软件层）、SSL/iptables（网络层）、服务器配置与补丁（系统层）

黑盒不可替代：部分特性漏洞只有 FUZZ 能挖出来。

## 四系统基线加固参数册（红蓝通用：蓝队加固自查 / 红队探测未达标项）

### Windows
- `gpedit.msc`：密码 8 位+3 类字符、90 天换、近 5 次不复用、5 次失败锁 30 分钟
- RDP 改端口：注册表 `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp\PortNumber`（默认 3389）
- 审核策略全部开"成功失败"；防火墙禁 135/137/138/139/445 + 白名单

### Linux
- `/etc/login.defs`：PASS_MAX_DAYS 180 / MIN_LEN 8；umask 077；`chattr +i /etc/shadow`
- sshd_config：Protocol 2、PermitRootLogin no、MaxAuthTries 6
- xinetd disable=yes 关 telnet/klogin/kshell/ntalk/tftp

### Oracle
- `utlpwdmg.sql` 配置 verify_function 复杂度；`alter profile DEFAULT limit FAILED_LOGIN_ATTEMPTS 10`
- audit_trail=os；监听器设口令；TNS 投毒防护：listener.ora 加 `SECURE_REGISTER_LISTENER_PROD=(TCP)/(IPC)`（日志出现 TNS-01194 即生效）

### Apache
- `Options` 去掉 Indexes（禁目录遍历）；`<Directory /> Deny from all`
- `<LimitExcept GET POST> Deny from all` + `TraceEnable Off`；隐藏版本；禁用 CGI

### 攻击者视角的"基线未覆盖处"

SNMP public 团体字、VSFTP 匿名与 root 登录、Oracle 默认账号 system/system、Windows 默认服务、3389 默认端口。

## 加固实施纪律（修复方）

三手段：版本升级/关端口服务/改配置项；临时手段：主机/网络 ACL、设备虚拟补丁。不轻易大版本升级，打补丁前备份、注意 32/64 位匹配。加固测试三件套：有效性/回退可逆/业务测试。
